# AGENTS.md

Klipper/Moonraker Telegram bot. Single Python app, no package structure: code lives in `bot/` as flat top-level modules, entrypoint is `bot/main.py`. PRs go to the `development` branch (see CONTRIBUTING.md).

## Commands

- Setup: `uv sync` (uv is the package manager; `pyproject.toml` + `uv.lock` are the source of truth).
- Full check (what CI runs, in this order): `uv run prek run --all-files --show-diff-on-failure --color=always` then `uv run pytest -v`. `prek` is a pre-commit drop-in; hooks = ruff check --fix, ruff format, mypy, codespell, pyproject-fmt, requirements sync.
- Single test: `uv run pytest -v tests/websocket_helper_test.py::test_name`.
- Run locally: `uv run python3 bot/main.py -c telegram_dev.conf`. Config sample sections: `tests/resources/*.conf`.
- Docker test builds target `linux/arm64` (buildx/QEMU required on x86 hosts). Dockerfile (opencv), Dockerfile-mjpeg, Dockerfile-dev (profiling tools).

## Non-obvious constraints

- Test files must be named `*_test.py` (pytest `python_files`), not `test_*.py`.
- `bot/` modules are imported flat (`from configuration import ...`) via pytest `pythonpath = ["bot"]`. When adding a module under `bot/`, add it to `[tool.ruff.lint.isort] known-first-party` or ruff isort will fail.
- Python 3.9 must keep working (ruff `target-version = py39`, mypy `python_version = "3.9"`, CI matrix 3.9–3.13). New deps need `python_version` environment markers matching the existing pins, and py3.9-compatible syntax.
- `scripts/requirements.txt` is autogenerated. After touching `pyproject.toml` or `uv.lock`, regenerate: `uv export --no-hashes --no-dev --no-emit-project -o scripts/requirements.txt` (a prek hook does this automatically). Never edit it by hand.
- `bot/main.py` replaces stdlib json globally: `sys.modules["json"] = orjson`. Don't "fix" this.
- mypy runs strict on `bot/` (`uv run mypy bot`); ruff lint set is aggressive (ANN, D, TRY, SLF, ...) — respect existing ignores in pyproject rather than loosening them.
- Bot tokens in logs are masked by `SensitiveFormatter` in `main.py`; if new secrets are introduced (e.g. Telegram `api_hash`), extend that regex.

## Architecture

- `bot/main.py` wires everything in its `__main__` block into module-level globals (`config_wrap`, `klippy`, `notifier`, `timelapse`, `camera_wrap`, scheduler) that handlers reference directly — only pure functions there are unit-tested. It builds `Klippy`, a camera subclass chosen by `[camera] type` (default `mjpeg`; classes in `bot/camera.py`), `Timelapse`, `Notifier`, `WebSocketHelper` (Moonraker websocket), and a python-telegram-bot `Application` in polling mode.
- Every new `telegram.conf` key must be added to `_KNOWN_ITEMS` of the section class in `bot/configuration.py`, otherwise it is reported as an unknown config field; sensitive values belong in `[secrets]`.
- Async stack: asyncio (+ uvloop on non-Windows), websockets to Moonraker, jobs via apscheduler `AsyncIOScheduler`. ffmpeg (system binary) is required for the `ffmpeg` camera type and timelapse encoding.
